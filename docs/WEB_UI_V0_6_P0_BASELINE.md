## 承認済み UI 方針

- iPhone 横持ち専用、タッチファースト。最優先は Godot Web のソロプレイ。
- STEP 4 v0.5 の画面モック（戦闘・拠点・装備倉庫・鍛冶屋・商人・宝箱）を外観と導線の基準にする。
- Battle Core、120枚カードの効果、24枚デッキ、Enemy/Encounter、経済・装備抽選、セーブ仕様を維持する。
- Windows 用デスクトップ UI と Web 専用 UI の見た目・操作を分離し、計算・状態遷移は共有する。
- 装備・倉庫・商人・宝箱・報酬・イベント・ルートでは**最初のタップは選択/詳細、同じ項目の次のタップで決定**。時間制限式の素早いダブルタップではない。
- 別項目タップは選択対象の変更。戻る・タブ切り替え・詳細の表示など非破壊操作は通常 1 タップ。
- 売却・分解など不可逆な操作には追加の確認ダイアログ。
- **戦闘中は例外**: カード選択→敵タップで使用確定（自分/対象不要カードは同じカードを再タップ、または「使用」）。カード選択のみで Mana 等を消費しない。
- ホバー必須操作をなくし、カード・装備の全文はタップ/長押しで表示する。
- 既存 Windows EOS/GDExtension のオンライン協力を Godot Web へ自動移植しない。現時点の Web 版はソロ優先。

## 公開とデータ保護

1. `feature/web-ui-v0-6` で実装と検証。 `main` はユーザーの追加承認まで変更しない。
2. GitHub Pages の現在の workflow は `main` への push を公開トリガーとする。開発ブランチはそれだけでは Web 本番公開しない。
3. UI 遷移・報酬・ショップのプレビュー操作では保存・ Gold / Mana / 在庫・装備状態を変更しない。
4. 「確認して決定」が 1 回だけサーバー/ローカル状態更新を発生するよう、二重送信・連打・選択切替を試験する。
5. Web セーブはブラウザ側ストレージにあるため、キャッシュ/サイトデータ削除をユーザーへ指示しない。公開切替前にセーブ互換性をテストする。
6. 新しい UI が iPhone 実機テストで合格するまでは `main` へ統合しない。
