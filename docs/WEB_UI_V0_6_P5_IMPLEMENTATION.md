# P5 — Web冒険中UI

実装ブランチ: `feature/web-ui-v0-6` のみ。GitHub Pages `main` は変更しない。

- `web_adventure_screen.gd`: 共通の冒険用横持ち画面。既存フェーズ `route`, `reward`, `service`, `defeat` のデータを直接表示。
- 道選択：通常/Elite/Boss/イベント/商人/宝箱/休憩。1回目は詳細、同じ候補の2回目だけ `choose_route`。
- 宝箱/戦闘報酬：候補装備と付属4カード・特殊効果の詳細、スキップ。再タップでのみ `take_reward`。
- イベント/休憩：Gold+80、素材+2、20%回復、35%回復。効果のプレビューだけなら保存しない。
- 旅の施設：商人・僧侶はラン中Goldとラン中戦利品を使用。拠点商人とは別。購入・在庫更新・HP回復・次戦支援を2回タップ確認。
- 敗北：戦利品の確保チェックは仮選択。各候補の装備詳細表示は取得操作ではない。最大確保数 `body_cap` を超える操作は却下。確保/帰還を2回タップして `resolve_defeat`。Run Goldは既存仕様通り喪失。
- P2戦闘の勝敗確定→Checkpoint→次画面、ソロ出発→道選択、タイトルからの保存再開の Web画面遷移を統合。
- 公式の `CampaignController` / `Region1RunController` を唯一の計算・保存主体として維持。既存カード・モンスター・装備の内部データ形式は変更しない。
- 選択時に現在の Campaign スナップショットを照合し、確定前に状態が変わっていたら処理しない。
- 既存Webシェルと戦闘画面を共有。Windowsは従来UIのまま。
- 専用テストは `tests/web_ui_p5_test.gd`。初期6装備とランをテスト用保存ファイルに生成し、報酬/商人/敗北などを分岐状態にして検査。本番セーブは変更しない。
- 未検証：実iPhone Safariのタップ/文字/スクロールと、全Region実周回における連続遷移。P6で実機テストを行う。
